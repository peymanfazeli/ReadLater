# CONTRIBUTING.md

## Change discipline
- One purpose per change.
- Prefer additive, local changes.
- Avoid unrelated formatting.
- Use descriptive commit messages.
- Update docs when behavior or setup changes.

## Review checklist
- Is the change inside the project root?
- Does it preserve privacy and locked-message rules?
- Is RTL handled?
- Are empty/loading/error states covered?
- Are tests appropriate?
- Is a module README updated?
- Are dependencies justified?
